# Подключение Telegram-группы

## Команда `/list`

В настроенной группе доступны `/list` и `/list@Housing_Monitor_NL_bot`.
Бот выводит все зарегистрированные источники объявлений, состояние мониторинга
и время последнего успешного сбора в UTC. Пауза поиска, отключение через environment
и отсутствие browser-подключения учитываются отдельно. Статус берётся из БД и
настроек приложения; команда не запускает новую проверку сайтов.

Обработчик включается вместе с `TELEGRAM_DELIVERY_ENABLED=true`, используя существующие
токен и ID группы. `TELEGRAM_COMMANDS_ENABLED=false` отключает только входящие команды.
Перед запуском примените миграции (`npm run db:deploy`). Privacy Mode можно оставить
включённым. Личные сообщения, чужие группы, команды другому боту и сообщения старше
пяти минут игнорируются. Ответ может задержаться, если в очереди есть уведомления.

Команды читаются через `getUpdates` каждые три секунды; одновременно можно запускать
несколько реплик приложения с общей БД. PostgreSQL блокирует параллельный polling,
а cursor и ответы в outbox сохраняются одной транзакцией. Повтор update не создаёт
нового ответа после рестарта. Отправка использует общий rate limit и правила UNCERTAIN.
Webhook автоматически не снимается: перед включением должен отсутствовать другой
потребитель updates. При ошибке API обработчик делает паузу (учитывает `retry_after`).
Не запускайте `telegram:chats` одновременно с активным обработчиком.

Бот проекта: `@Housing_Monitor_NL_bot`. Для подключения и тестовой отправки есть CLI.
Worker автоматической доставки и transactional outbox реализованы.
Для включения нужны Telegram-переменные и TELEGRAM_DELIVERY_ENABLED=true;
подробности: [outbox.md](outbox.md).

## Локальные секреты

Скопировать `.env.example` в `.env`, если файла ещё нет. Вставить токен из
BotFather в редакторе, без отправки в чат и без передачи в аргументах команд:

```dotenv
TELEGRAM_BOT_USERNAME=Housing_Monitor_NL_bot
TELEGRAM_BOT_TOKEN=<токен из BotFather>
```

`.env` исключён из Git. Не публиковать его и не включать в диагностические выводы.

## Получение ID группы

1. Создать группу, добавить бота и разрешить отправку сообщений.
2. Отправить в группе `/start@Housing_Monitor_NL_bot`. Ответа пока не будет: обработчик
   команд ещё не реализован, команда нужна для появления входящего update.
3. Выполнить:

```sh
npm run telegram:check
npm run telegram:chats
```

Команда проверяет соответствие токена username, затем показывает только ID групп,
без переписки и персональных данных. Если групп несколько, выбрать нужную вручную.
При пустом списке отправить команду в группу ещё раз: Telegram хранит updates
не дольше 24 часов, вывод ограничен первыми 100 неподтверждёнными updates.
CLI не подтверждает/удаляет updates и не снимает webhook. Не запускать discovery
параллельно другому потребителю updates этого бота.

Добавить выбранный ID в `.env`:

```dotenv
TELEGRAM_CHAT_ID=-1001234567890
```

Для обычной группы ID также отрицательный, но может не начинаться с `-100`.
Privacy Mode можно оставить включённым. Если группа преобразована в supergroup,
нужно обновить ID. CLI учитывает события миграции в доступных updates.

## Проверка отправки

```sh
npm run telegram:test
```

Команда отправляет одно тестовое сообщение в выбранную группу. При тайм-ауте
проверить группу перед повтором: сообщение могло быть доставлено. Автоматического
повтора нет. Запуск приложения не отправляет тестовые сообщения.

## Railway

Локальный `.env` не переносится в Railway. После проверки добавить
`TELEGRAM_BOT_USERNAME`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` через Variables
сервиса приложения. Скрипты входят в Docker-образ; в его shell доступны эти же
команды npm. Токен задаётся через Variables, без вставки в shell-команды.

API: [getMe](https://core.telegram.org/bots/api#getme),
[getUpdates](https://core.telegram.org/bots/api#getupdates),
[sendMessage](https://core.telegram.org/bots/api#sendmessage).
