# Rentola — Groningen

Источник: https://rentola.nl/en/rent?location=240117&order=desc

Согласовано 17 октября 2026: Groningen, объявленная месячная аренда до €1500 включительно, только отдельное жильё без комнат. Дата публикации не ограничена. Дополнительные расходы из описаний не прибавляются к цене. Source ID: `rentola:groningen-homes`.

Публичный HTTP GET, без аккаунта и browser worker. Заголовок `Accept-Language: en` соответствует URL; с `nl-NL` сайт перенаправляет на `/huren`, такой редирект не принимается. Цена и минимальная площадь применяются на сервере, исходная ссылка сохраняется. Обходятся все страницы, включая объекты за пределами бюджета: на исследовании 285 объектов, 14 страниц, по 21 объекту. Число страниц ограничено 100, тело ответа — 8 MiB, время всего прохода — 140 секунд. Страницы читаются последовательно с паузой 300 мс. Описания — партиями до двух запросов, со сдвигом старта 300 мс и паузой 300 мс между партиями; обе операции завершаются до возврата ошибки. HTTP 502/503/504 и транспортные сбои повторяются до трёх попыток; 429 даёт cooldown, 401/403 — BLOCKED.

Адаптер декодирует строковые `self.__next_f.push` как JSON, не исполняет JavaScript. Проверяет эхо location/order/page, отсутствие неожиданных фильтров, город карточек и included, пагинацию, полноту, уникальность ID/URL внутри страницы и между страницами. JSON-LD сверяется с публичным состоянием: URL, название, цена, валюта и адрес. Смена счётчика прерывает текущий обход; один полный повтор описан ниже. Частичный ответ, редирект, challenge и ошибка не считаются успешным нулём. Реальный пустой ответ для этой выдачи пока не подтверждён; ноль завершается `EMPTY_SEARCH_UNCONFIRMED`.

Категории Rentola ненадёжны: реальная карточка Jennerstraat 12 помечена `apartment`, но описание предлагает три студенческие комнаты. Поэтому категории `room`, `student apartment`, неизвестные и неоднозначные типы исключаются; проверяются названия и описания всех кандидатов в пределах цены/площади. Комнаты, совместные бытовые помещения и признаки несамостоятельного жилья исключаются. Неоднозначный `house` без явного названия жилья исключается. Объявления с явно пустым описанием исключаются, так как самостоятельность жилья подтвердить нельзя. Правила консервативны: упоминание отдельных комнат в описании может исключить и полноценное жильё. Типы и описания остаются утверждениями агрегатора; фактическая доступность у исходного арендодателя не подтверждается.

Только `https://schema.org/InStock` одновременно в выдаче и описании допускает объект. Чужие домены, credentials, query/hash в detail URL запрещены. Поддерживаются новые slug с `-p…` и старые с шестизначным hex suffix. Оценочная площадь не используется как известная; при заданном минимуме объект без достоверной площади исключается. Ссылка ведёт на Rentola; платный контакт с арендодателем не используется.

18 октября 2026: production `SEARCH_METADATA_CHANGED` вызван реальным slug `student_apartment-for-rent-at-bottelroosstraat-1-groningen-p39bae8`. Подчёркивание разрешено в slug как в состоянии выдачи, так и в detail URL; проверка домена, пути и suffix сохраняется. Студенческие комнаты по-прежнему исключаются. Исправленный live smoke без БД/Telegram: 290 карточек, 14 страниц, 69 подходящих объектов.

19 октября 2026: после успешного прохода в 05:31 UTC (290 карточек, 69 подходящих объектов) production семь раз подряд завершился `SEARCH_CHANGED_DURING_RUN`, начиная с 05:44 UTC. Публичный live smoke воспроизвёл устойчивое расхождение: первая страница `order=desc` — 274 карточки / 14 страниц; страницы 2, 3 и 13 — 272 / 13, на странице 13 — 20 карточек. Все HTTP 200. Повторные запросы с `Cache-Control: no-cache` и `Pragma: no-cache` дают те же счётчики и ID; ответы имеют `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`, Cloudflare — `DYNAMIC`. Это несогласованность данных выдачи Rentola; конкретный внутренний механизм кеширования или подсчёта по этим ответам установить нельзя. [Диагностический запуск](https://github.com/LordAsmodey/housing-monitor-nl/actions/runs/39216138668).

При `SEARCH_CHANGED_DURING_RUN` адаптер отбрасывает все карточки неудачного обхода, ждёт одну секунду и ровно один раз читает весь тот же каталог с поддерживаемой сайтом сортировкой `order=rent_asc`. Исходная ссылка и критерии поиска сохраняются; меняется только порядок полного обхода. Повтор начинает с первой страницы, заново проверяет все счётчики, полноту, уникальность, фильтры и JSON-LD с точным URL новой сортировки. Описания читаются только после успешной проверки полного каталога. Общий таймаут 140 секунд, сигнал отмены, lease и настройки едины для обеих попыток. HTTP-ошибки, блокировки, дубли и изменения структуры сами по себе повтор не запускают. Если повтор тоже невалиден, runner сохраняет FAILED/DEGRADED без записи частичного результата и без новых уведомлений; третьей попытки нет.

Ошибка несогласованности теперь содержит только техническую диагностику: сортировку, номер страницы, ожидаемые и фактические totalCount/totalPages. Эти поля и успешное восстановление попадают в Railway log; правила очистки Sentry не меняются. Live smoke печатает итоговую сортировку и `recoveredFrom`, чтобы успешное восстановление было видно без сохранения HTML, адресов и описаний.
