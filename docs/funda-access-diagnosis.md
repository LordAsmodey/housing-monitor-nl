# Funda: диагностика доступа из Railway

Проверка выполнена 12 октября 2026 года в Railway production, регион us-west2.
Причина текущего ACCESS_BLOCKED установлена: поисковые HTTP-запросы получают
403 Access Denied от AkamaiGHost. Обычный Chromium также не получает выдачу поиска:
при HTTP 200 он показывает страницу проверки человека.

## Что проверено

Отдельный одноразовый сервис funda-access-diagnostic, ID
`64469536-f577-4dab-926c-ab203fdbc82c`, без секретов приложения, БД, Telegram, домена и volume.
Образ: официальный `mcr.microsoft.com/playwright:v1.56.1-noble`, Chromium 141.0.7390.37.
Установлен соответствующий Playwright 1.56.1. Нет stealth-плагинов, внешних proxy,
подмены fingerprint, входа или решения CAPTCHA. Chromium headed запускался с Xvfb.
Контекст один на последовательность страниц; сайт мог устанавливать обычные cookies.

Адреса: главная Funda; простой поиск Groningen; тот же URL поиска Groningen +30 км,
до €1500 с сортировкой по дате, который использует production-модуль.

| Клиент | Главная | Простой поиск | Поиск с фильтрами |
| --- | --- | --- | --- |
| Node fetch с заголовками production-модуля | 200, сайт Funda | 403, Akamai Access Denied | 403, Akamai Access Denied |
| Chromium headless | 200, защитная страница | 200, защитная страница | 200, защитная страница |
| Chromium headed + Xvfb | 200, сайт Funda и баннер cookies | 200, проверка человека, 0 карточек | 200, проверка человека, 0 карточек |

Защитная страница имеет заголовок «Je bent bijna op de pagina die je zoekt».
Видимый текст сообщает, что для защиты платформы иногда требуется проверить,
что посетитель — человек. В headed-прогоне тело содержит признаки captcha/Akamai;
контекст получил cookies Akamai, однако поиск остался закрыт. Значения cookies не записывались.

Между прогонами один redeploy повторил прежний snapshot, а отдельный запуск через
xvfb-run не дошёл до Node. Эти промежуточные deployments не используются как
доказательство headed-доступа. Итоговый сценарий сам запускает Xvfb и ограничивает всю
работу четырьмя минутами. Restart policy диагностического сервиса — NEVER, cron отсутствует.

## Вывод и границы

Сетевое соединение и TLS работают: главная возвращает содержимое Funda. Отказ на поиске
возникает до парсинга HTML; простая замена селекторов его не исправляет. HTTP 200 в браузере
сам по себе не означает успешный доступ к данным — обязательна проверка содержимого.
Распознавание наблюдаемой защитной страницы добавлено в guardPage как HUMAN_CHECK/BLOCKED.

Прогоны проведены отдельным сервисом в том же регионе, а не внутри production-контейнера.
Одинаковый исходящий IP не подтверждён. Поэтому нельзя утверждать, что блокируется весь
Railway или только конкретный IP: могут влиять IP-репутация, клиент, TLS и сессия.
Также не проверены доступ после ручной проверки, авторизованный аккаунт и другие регионы.
Успешного чтения реальных карточек и уведомлений в этих прогонах нет.

Следующий технический шаг — проверка обычной браузерной сессии после ручного прохождения
требуемой проверки и, если доступ появляется, безопасное сохранение этой сессии.
Изменять production-монитор на браузер до такого подтверждения преждевременно.

## Повторение

В официальном образе Playwright с совпадающей версией:

```sh
node scripts/funda-diagnose.cjs
node scripts/funda-diagnose.cjs --headed
```

Сценарий читает три публичных адреса через HTTP и браузер, пишет ограниченные JSON-сводки
и завершает работу. Он не записывает объявления, не подключается к БД и не отправляет Telegram.
Не выводит значения cookies, переменные окружения или полный HTML. Лог содержит время,
статус, выборочные response headers, заголовок, SHA-256, число ссылок и небольшой видимый фрагмент.
