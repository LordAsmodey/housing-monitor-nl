# Pararius — Groningen +25 км

[Требования в Notion](https://app.notion.com/p/402d10c6e6ab816ba5d4dfe6407fa7e7?pvs=204)

Поиск пользователя: <https://www.pararius.nl/huurwoningen/groningen/0-1500/straal-25>.

Только квартиры, студии и дома без комнат; объявленная или базовая месячная аренда
до €1500 включительно, без ограничения даты публикации. `Totale huurprijs` сохраняется
и показывается отдельно, разница не объявляется servicekosten.

## Подключение и контракт

Источник `pararius:groningen-25km-homes` подключён к scheduler и transactional outbox.
Последняя зафиксированная запись Notion подтверждает выпуск и первый полный тихий
production baseline 18.10.2026; это не live-проверка здоровья сегодня.
Длительная устойчивость и естественная доставка нового объявления отдельно не доказаны.

Отдельный headed Chrome/Patchright worker использует свой зашифрованный persistent-профиль.
CAPTCHA при необходимости проходит пользователь. Проверяются параметры поиска,
счётчик, последовательность и полнота всех страниц, ID/URL до исключения комнат.
Частичный обход и ошибки не считаются успехом; неподтверждённый ноль —
`EMPTY_SEARCH_UNCONFIRMED`. Только available уведомляется; unknown, Verhuurd,
Onder optie и Gereserveerd не уведомляются.

Свежую первую страницу можно переиспользовать только при точном совпадении URL,
подтверждённом HTTP 2xx, возрасте до 60 секунд после DOMContentLoaded и полной
валидации. Последующие страницы проходят обычную навигацию. Это снижает число запросов,
но не гарантирует отсутствие повторной проверки человека.

Лимиты текущего адаптера: 20 страниц, 600 карточек, 5 MiB на ответ, до трёх попыток
на транспортные ошибки и 502/503/504. 429 даёт cooldown, 401/403 — BLOCKED.
Бюджет сбора — до 300 секунд, lease — 360 секунд. Расширение поиска требует проверки
контракта адаптера. Основная логика — `scripts/pararius-core.cjs`,
`scripts/pararius-runner.cjs`, worker — `scripts/pararius-browser-session.cjs`.

## Развёртывание

Для нового окружения создать отдельный Railway service из того же репозитория с Dockerfile `Dockerfile.pararius-browser`, healthcheck `/health` и собственным volume `/data`. Не использовать volume или ключи других источников. Переменные worker соответствуют существующему браузерному протоколу:

- `BROWSER_PUBLIC_ORIGIN`: HTTPS-домен нового service;
- `BROWSER_WORKER_TOKEN`: случайный секрет не короче 32 символов;
- `BROWSER_STATE_KEY_HEX`: отдельный случайный ключ 32 байта в hex;
- `BROWSER_ACCESS_KEY`: отдельный временный секрет не короче 32 символов;
- `BROWSER_ACCESS_EXPIRES_AT`: срок временного доступа в ISO формате;
- необязательно `BROWSER_IDLE_TIMEOUT_SECONDS=60` для остановки браузера между проходами (по умолчанию выключено).

Browser state зашифрован AES-GCM. Worker закрыт Bearer token; отладочный порт не публикуется. Одноразовая recovery-ссылка действует 24 часа. Main-frame navigation ограничена доменами Pararius, приватные адреса блокируются. В варианте Chrome сторонние ресурсы сохраняются, как у Huurwoningen; Cloudflare challenge остаётся доступен для ручной проверки.

Перед первым включением в новом окружении выполнить read-only smoke (без БД и Telegram):

```sh
node --env-file=.env scripts/pararius-check.cjs
```

Для этого локально настроить `PARARIUS_BROWSER_ORIGIN` и `PARARIUS_BROWSER_TOKEN`. При challenge открыть выданную worker recovery-ссылку, пройти проверку вручную, открыть «Поиск жилья» и сохранить сессию. Затем повторить smoke. В приложении задать оба этих значения для включения источника. Без них источник не запускается, и админка показывает отсутствие runtime. Удаление пары выключает runtime без сброса истории; обычная пауза — через админку.



## Recovery и выпуск

401 на `POST /api/login` означает отказ локального входа recovery UI и сам по себе
не доказывает Cloudflare-блокировку. Проверяйте код именно browser service,
а не только приложения. Для нового доступа используется авторизованный
`POST /worker/recovery/renew`. Повторное открытие в том же браузере использует
действующую cookie; погашенный ключ в другом браузере вход не даёт.
Ссылка и ключи не публикуются в документации.

При изменении worker сохранить volume и ключи, сверить `/health.release`
с выпущенным SHA, проверить вход/повторный вход и затем read-only полный сбор.
Не выполнять новый деплой или ротацию доступа только из-за старого архивного статуса.
