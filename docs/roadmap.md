# План реализации

## P0 — следующий этап

1. Получить 2–3 реальных сайта, включая один с авторизацией, и критерии аренды.
2. Проверить правила источников и разрешённые API/RSS/email.
3. Сравнить Stagehand, Browser Use и прямой Playwright + LLM: стоимость, восстановление, надёжность.
4. Проверить цикл: исследование → декларативный сценарий → повтор без LLM.

## P1 — вертикальный срез MVP

- Доработать Prisma-схему и зафиксировать миграцию: SearchDefinition, BrowserSessionRef, Scenario/ScenarioVersion, RunFinding, ListingObservation, AlertSubscription, RecoveryAttempt, AuditEvent.
- SiteProfile manager, шифрованное browser state, блокировка профиля, закрытый ввод секретов.
- Onboarding, Scenario Executor, validation и ограниченное recovery.
- Scheduler/BullMQ, отсутствие overlap, retry/backoff и cooldown.
- Нормализация, baseline, дедупликация, события изменения условий.
- Transactional outbox, Telegram sender, DLQ и диагностика неоднозначной доставки.
- Интеграционные тесты и запуск 2–3 реальных источников.

## P2/P3

Rollback сценариев, метрики, аномалии, admin alerts и команды; затем cross-source matching, 10–20 источников, управление фильтрами и подписки.

## Нерешённые параметры

Список сайтов, точная география, бюджет аренды/площадь/комнаты, VPS/LLM-бюджеты, AI-провайдер, аккаунты, Telegram channel ID, агентства/новостройки и допустимое время восстановления. Для инициализации не требуются, перед продуктивным запуском нужны.

## Ограничение гарантии доставки

Уникальный ключ outbox предотвращает дубли внутри приложения, но Telegram Bot API не поддерживает клиентский idempotency key. При отправке с последующим сетевым тайм-аутом или падением до сохранения message ID нельзя гарантировать exactly-once. Нужно согласовать поведение для неоднозначного результата: повтор с риском дубля или ручная проверка с риском задержки. Обычные повторные проверки и рестарты после подтверждённой записи доставки не должны создавать дубли.

## Границы текущей схемы

Prisma-схема — стартовый проект моделей, ещё не production-контракт. JSON filters и ссылки на секреты не заменяют валидацию, безопасное хранилище и SSRF-защиту. Эти механизмы будут реализованы до первого подключения сайтов. Redis/BullMQ, Playwright и AI SDK подключаются вместе с соответствующим рабочим модулем.
