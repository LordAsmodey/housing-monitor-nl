# План реализации

## Решение от 12.10.2026 — MVP без LLM

LLM исключён из обязательного MVP и ближайшего плана по решению пользователя.
Мониторинг работает через детерминированные HTTP/Playwright адаптеры; подключение
источников и исправление адаптеров выполняет разработчик. При сбоях используются
валидация, ограниченные повторы, диагностика и ручное восстановление.
Обязательные CAPTCHA/MFA требуют участия человека.

Ближайшие приоритеты: подтвердить стабильную работу текущих источников в течение
нескольких дней, добавить `/status` с последними успешными проверками и состоянием
доставки, уведомлять об устойчивых сбоях без спама. Новые источники подключать
по полезности для поиска жилья.

## Текущий срез PostgreSQL / Telegram

- Реализованы Prisma-подключение, начальная миграция и readiness endpoint.
- Реализованы baseline, дедупликация и transactional outbox для валидированных результатов.
- Реализован Telegram worker с durable rate limit, retries 429, DEAD_LETTER и UNCERTAIN.
- Добавлены интеграционные тесты и CLI ручного разрешения проблемных заданий.
- 12.10.2026 проверена доставка через штатный production-worker Railway: SENT,
  одна попытка, Telegram message ID 6; повтор CLI не создал дубль. Добавлен
  повторяемый `outbox:smoke`; детали и границы проверки — в [outbox.md](../outbox.md).
- Funda и Huurwoningen подключены через отдельные браузерные сервисы, Woldring — через HTTP.
  Все три источника используют расписание 15 минут, PostgreSQL lease, baseline и существующий outbox.
  Funda использует пользовательский фильтр «за сегодня»; инструкции и границы проверки —
  [funda.md](../funda.md), [huurwoningen.md](../huurwoningen.md), [woldring.md](../woldring.md).
- Длительная эксплуатация и источник с авторизацией ещё не подтверждены.
  BullMQ и расширенные модели остаются в backlog; LLM — в дальнем backlog без срока.

## P1 — вертикальный срез MVP

- Доработать Prisma-схему и зафиксировать миграцию: SearchDefinition, BrowserSessionRef, Scenario/ScenarioVersion, RunFinding, ListingObservation, AlertSubscription, RecoveryAttempt, AuditEvent.
- SiteProfile manager, шифрованное browser state, блокировка профиля, закрытый ввод секретов.
- Ручное подключение источников, детерминированный executor, validation и ограниченные повторы с ручным восстановлением.
- Scheduler/BullMQ, отсутствие overlap, retry/backoff и cooldown.
- Нормализация, baseline, дедупликация, события изменения условий.
- Transactional outbox, Telegram sender, DLQ и диагностика неоднозначной доставки.
- Интеграционные тесты и запуск 2–3 реальных источников.

Дополнительные сайты, площадь/комнаты, включение service costs в €1500, аккаунты источников, агентства/новостройки и допустимое время восстановления. Telegram-группа уже подключена. LLM-бюджеты и AI-провайдер не требуются для текущего MVP.

## Ограничение гарантии доставки

Уникальный ключ outbox предотвращает дубли внутри приложения, но Telegram Bot API не поддерживает клиентский idempotency key. При отправке с последующим сетевым тайм-аутом или падением до сохранения message ID нельзя гарантировать exactly-once. Нужно согласовать поведение для неоднозначного результата: повтор с риском дубля или ручная проверка с риском задержки. Обычные повторные проверки и рестарты после подтверждённой записи доставки не должны создавать дубли.

## Границы текущей схемы

Prisma-схема — стартовый проект моделей, ещё не полный production-контракт. JSON filters и ссылки на секреты не заменяют валидацию, безопасное хранилище и SSRF-защиту. Существующие браузерные сервисы используют Playwright и шифрованное состояние; расширение общей модели выполняется вместе с соответствующими модулями. BullMQ остаётся в backlog, AI SDK — в дальнем backlog.
