# Gruno Verhuur

[Каталог](https://www.grunoverhuur.nl/woningaanbod/groningen) читается через обычный HTTP,
без аккаунта или дополнительного browser service. Подключение устроено как Woldring:
общий `runFunda`, PostgreSQL lease, отдельный baseline и существующий Telegram outbox.
Source ID: `gruno:groningen-apartments-studios-1500`.

## Фильтры

Фильтрация выполняется в модуле после проверки полноты всего каталога:
Groningen по указанной ссылке (без радиуса), аренда, объявленная цена до €1500 включительно,
квартиры и студии. Ограничений площади, числа комнат, даты публикации или заселения нет.
Существующие параметры Funda и других источников не меняются.

Студенческие комнаты, `Studentenkamer`, `kamerverhuur`, semi-/onzelfstandige предложения
исключаются. Для кандидатов дополнительно читается подробное описание: явные признаки
общей кухни/санузла исключают объект. Общий подъезд сам по себе не исключает квартиру.
Отбор консервативный: ошибочно помеченная сайтом как Studentenkamer квартира тоже исключается;
отсутствие признаков совместного пользования не гарантирует юридическую самостоятельность.
Временные самостоятельные квартиры не исключаются отдельным ограничением срока договора.

Фильтры задаются константой `FILTERS` в `scripts/gruno-core.cjs` и сохраняются в SiteProfile.
`GRUNO_MONITORING_ENABLED=false` приостанавливает источник без сброса baseline.
По умолчанию источник включён после развёртывания этой ветки.

## Данные и уведомления

ID берётся из `Referentienummer`, canonical URL не содержит контекста поиска.
Цена в `rentPrice` — объявленная цена, а не вычисленная базовая аренда.
Servicekosten сохраняются отдельно, с признаком включения в цену, если он указан явно.
Для Gruno уведомление **никогда не складывает** объявленную цену и servicekosten:
€1232 с включёнными €130 остаётся €1232. Если состав цены неясен, это отражается в тексте.
Бюджет применяется к объявленной цене; это не гарантия полной стоимости проживания.
Дата публикации читается из `Aangeboden sinds`, дата заселения — из `Aanvaarding`.
Неизвестные даты и расходы не выдумываются. Дата без времени сохраняется как UTC-полночь.

Первый полный проход сохраняет подходящие доступные и недоступные объявления без рассылки.
Далее общий outbox уведомляет о новых доступных объектах и `unavailable → available`.
Уникальный ключ на объект и канал не допускает повторного уведомления того же объекта.
Если статус отсутствует и в каталоге, и в деталях, сохраняется `unknown` без уведомления.
Только для Gruno общий runner требует явное `available` для отправки; переход
`unknown → available` тоже уведомляется. Другие источники сохраняют прежнее поведение.
Карточки, пропавшие из каталога, автоматически не объявляются сданными.

## Валидация и границы

Проверяются заголовок, общий count, количество карточек на каждой странице, шаг пагинации,
стабильность count, дубли ID/URL, обязательные поля и известные статусы.
Детали сверяются с каталогом по ID, цене и доступности. Отсутствующий badge каталога
означает unknown; подробная карточка уточняет его, если он указан. Неизвестная структура, метка статуса,
несогласованная/неполная выдача — ошибка, не успешный нулевой результат.
Ошибки не меняют baseline/lastSuccessAt; другие источники продолжают работать.

Максимум 20 страниц/200 карточек, 80 подробных карточек, 8 МБ на ответ, 120 секунд на проход.
Для временных сетевых ошибок и 502/503/504 — до трёх попыток; 429 — cooldown,
401/403/проверка человека — BLOCKED и повтор не раньше шести часов.
Redirect не выполняется, навигация ограничена HTTPS доменом www.grunoverhuur.nl.

Публичный robots.txt проверен 14.10.2026: запреты относятся к `ReturnUrl` и `object-video`,
не к читаемым страницам. Это техническое наблюдение, а не подтверждение отдельного разрешения.

## Проверки

- `node --test test/gruno.test.mjs`: реальные HTML-фрагменты, фильтры, пагинация,
  даты, состав цены, ошибки HTTP, ограничения и запрет внешних URL.
- `npm run test:integration`: отдельный source, baseline, lease, переходы статуса,
  отсутствие дублей, формат цены и rollback на одноразовой PostgreSQL БД.
- `node scripts/gruno-check.cjs`: полный read-only live smoke без БД, Telegram и Sentry.
  GitHub workflow `Gruno live smoke` выполняет его для изменений адаптера.

История первичного исследования: [gruno-research.md](gruno-research.md).

Live smoke 14.10.2026: 31 объект на 4 страницах, 11 подходящих подробных карточек,
10 с подтверждённой доступностью и 1 с `unknown`. Первый baseline всё равно не рассылается.
