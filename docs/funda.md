# Автоматическая проверка Funda

Модуль подключён к NestJS, PostgreSQL и существующему Telegram outbox. Fast Path читает
HTML через HTTP, не вызывает LLM, не запускает JavaScript со страниц и не требует
ручного импорта. Источник: `funda:groningen-30km-1500-3d`.

## Согласованные фильтры

- Groningen и окрестности в радиусе 30 км. Центр расчёта: 53.2194 N, 6.5665 E;
  расстояние по прямой (haversine), включительно до 30 км.
- Объявленная месячная аренда до €1500 включительно. Service costs пока не прибавляются:
  их учёт пользователь не уточнил. Покупка, парковки/кладовые, сдача под опцией и уже сданные объекты исключены.
- Дата публикации не старше 72 часов при каждой проверке. Дата обнаружения не заменяет
  дату публикации. Дата без времени считается полуночью Europe/Amsterdam; на границе окна
  это может исключить часть объявлений третьего дня. Если Aangeboden sinds скрыто за входом,
  читается публичная дата Op Funda. Относительные даты не угадываются.

Поиск отправляет фильтры географии/цены и сортировку от новых к старым. Свежесть и расстояние
дополнительно проверяются по карточкам. `publication_date` не отправляется: его текущий
формат не подтверждён. Сценарий v1 ожидает обычные ссылки карточек, число результатов,
пагинацию, пары `dt/dd` и JSON-LD адрес/координаты. Неподдерживаемая разметка завершает
проверку ошибкой и требует следующего изменения адаптера.

## Включение

```sh
npm ci
npm run db:generate
npm run db:deploy
npm run build
# Прочитать Funda без записи в БД и без отправки:
npm run funda:check -- --dry-run
```

Funda запускается автоматически при старте приложения. Нужен существующий `TELEGRAM_CHAT_ID`;
`MONITOR_INTERVAL_SECONDS` по умолчанию 900. Для доставки также нужны `TELEGRAM_DELIVERY_ENABLED=true`
и `TELEGRAM_BOT_TOKEN`. Секреты остаются в переменных окружения.

При обычном развёртывании Railway применяет миграцию до запуска. После слияния PR и деплоя
первая проверка выполняется автоматически, без дополнительных переменных включения.
Проверки стартуют через 5 секунд после старта приложения, затем по сохранённому расписанию.
Опрос готовности расписания каждые 5 секунд не делает HTTP-запросов при `nextCheckAt` в будущем.

Один запуск с теми же блокировками и расписанием:

```sh
npm run funda:check -- --once
```

Первый успешный запуск сохраняет baseline без уведомлений. Следующие новые объявления
создают задания outbox. Повторы сохраняют существующие объявления и не создают дублей.
Данные, outbox и успешный статус запуска фиксируются одной транзакцией. CLI не запускает
отдельный Telegram sender; сообщения отправляет штатный worker приложения.

## Ограничения и диагностика

- Разрешён только HTTPS на www.funda.nl и пути поиска/аренды; пользовательские URL,
  редиректы, дополнительные параметры поиска и внешние домены не загружаются.
- До 5 страниц/60 карточек за запуск, 5 MiB на HTML, 15 секунд на запрос, 120 секунд
  на сбор и минимум 1 секунда между запросами. Превышение лимитов не считается успехом.
- Отсутствующая пагинация, несогласованное число карточек, потерянная дата или координаты
  переводят источник в DEGRADED. Уже собранные карточки такого запуска не сохраняются.
- HTTP 401/403 и страница человеческой проверки дают BLOCKED и cooldown 6 часов.
  HTTP 429 учитывает Retry-After (максимум сутки); остальные ошибки повторяются не чаще интервала.
- В `MonitoringRun.errorCategory` сохраняется категория, без HTML/секретов. `lastAttemptAt`
  обновляется при попытке; `lastSuccessAt` и baseline остаются прежними при ошибке.
- Lease 180 секунд защищает от параллельных экземпляров и CLI. Просроченный runner
  не может записать результаты. После прерывания RUNNING закрывается как WORKER_INTERRUPTED.

Нет браузерного/LLM recovery, автоматического входа или обработки CAPTCHA. Если Funda
требует JavaScript/авторизацию или меняет структуру, HTTP Fast Path может не сработать;
это отражается состоянием источника, а не ложной пустой выдачей.

## Исследование и проверка

Проверено по публичным материалам Funda:

- [Описание поиска и сохранённых уведомлений](https://www.funda.nl/en/meer-weten/producten-en-diensten/zoeken-op-funda/):
  радиус поиска и email/push уведомления существуют. Email не выбран для этого модуля.
- [Пример карточки аренды](https://www.funda.nl/detail/huur/groningen/appartement-brugstraat-3-a/80987170/):
  месячная аренда и service costs представлены раздельно.
- [Условия Funda](https://www.funda.nl/voorwaarden-en-beleid/gebruiksvoorwaarden/) описывают
  ограничения автоматизированного извлечения. Пользователь явно поручил подготовить
  автоматический модуль; программного требования письменного разрешения не добавлено.

Локальные тесты используют синтетические HTML-контракты: границы цены/свежести/радиуса,
Amsterdam/DST, фильтрация, пагинация, SSRF-ограничения, HTTP ошибки и неполные результаты.
Интеграционные тесты с отдельной PostgreSQL проверяют baseline, дедупликацию, leases,
сохранение последнего успеха и диагностику. CI также проверяет TypeScript, сборку и Prisma.

Web-инструмент смог открыть публичный поиск Groningen и карточку аренды: подтверждены
число результатов, месячная аренда, статус, скрытое Aangeboden sinds и публичное Op Funda
с датой 5-10-2026. Полный URL поиска с радиусом/бюджетом через web-инструмент не открылся.
HTTP-запуск самого модуля, соответствие сырой HTML-разметке и доставка реальных объявлений
в этой задаче **не подтверждены**: сетевой доступ рабочего окружения оказался недоступен.
Тестовые HTML не являются живыми captures.
После деплоя модуль запускается автоматически. В runtime-логах есть Funda automatic monitoring
scheduled и результат проверки: Funda check succeeded с inspected/matched/created/baseline/runId
либо Funda check failed с category. Агент проверяет deployment SUCCESS, запуск модуля и результат
чтения по Railway MCP; консоль пользователя для этой проверки не нужна.
Это подготовленный автоматический модуль, а не подтверждённый
работающий мониторинг Funda в production.
