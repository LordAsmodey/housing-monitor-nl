# Huurwoningen

Согласованный поиск: <https://www.huurwoningen.com/in/groningen/?price=0-1500&radius=25&since=1&available_from=within_3_months&filters%5Boffer_type%5D%5B0%5D=homeswap>.
`available_from=within_3_months` — «Beschikbaar vanaf → Binnen 3 maanden»: доступность для заселения в ближайшие три месяца. Это не свежесть публикации и не срок договора.
Радиус — 25 км, цена `0-1500`, свежесть `since=1`. Параметр `filters[offer_type][0]=homeswap` сохраняется буквально из пользовательской ссылки: по уточнению пользователя он исключает обмен жилья, который включён по умолчанию. Комнаты и студии дополнительно не исключаются.
Все условия применяет поиск Huurwoningen; сервис не фильтрует повторно цену, дату или тип предложения в карточках.

С 13 октября 2026 production использует headed Google Chrome через Patchright 1.63.0
в отдельном сервисе, с volume и ключом AES-256-GCM. Испытание принято пользователем
14 октября после 95 успешных проверок; дополнительный observer выключен.
[Сборка, профиль, деплой и итог испытания](huurwoningen-experiment.md).
Сессия Funda не используется. Сбор читает только карточки и ссылки пагинации из выдачи,
проверяет отображение фильтров, полноту относительно общего числа результатов и отсутствие повторов.
Пределы: 20 страниц, 600 объявлений, 5 МБ HTML на страницу; превышение — ошибка, а не частичный успех.
Пустая выдача подтверждается обычным нулевым счётчиком либо явным сообщением
«Helaas, er zijn geen woningen gevonden» в секции `no-search-results`, при сохранённых
фильтрах и отсутствии карточек и пагинации. Счётчик рекомендаций «в окрестностях»
не используется как число результатов согласованного поиска; противоречивые данные остаются ошибкой.
Необязательная дата публикации не извлекается из отдельных карточек. Доступность карточки сохраняется как `unknown`: фильтр даты заселения не подтверждает статус конкретного объекта.
Карточки с явно указанным «Prijs op aanvraag» сохраняются без числовой цены; это не ошибка и не нулевая аренда.

Source ID: `huurwoningen:groningen-25km-within-3-months`. Первый успешный сбор создаёт собственный baseline без рассылки.
При сужении поиска прежний Source ID, baseline и дедупликация сохраняются. Версия сценария обновляется, чтобы новые параметры применились при первом запуске после развёртывания.
Новые объявления затем проходят существующий transactional outbox в ту же Telegram-группу.
Проверка каждые `MONITOR_INTERVAL_SECONDS` (900 по умолчанию); lease в PostgreSQL защищает от overlap и повторного baseline.
Изменение цены/доступности и совпадения с Funda пока не создают отдельных событий.

## Включение

В приложении задаются обе переменные `HUURWONINGEN_BROWSER_ORIGIN` и `HUURWONINGEN_BROWSER_TOKEN`.
Без них источник выключен. Origin допускает только HTTPS `*.up.railway.app` или HTTP `*.railway.internal`;
токен отдельный от Funda и совпадает с `BROWSER_WORKER_TOKEN` нового сервиса.

Текущий контейнер: `Dockerfile.huurwoningen-experiment`, конфигурация `railway.huurwoningen.json`.
Старый контейнер: `Dockerfile.huurwoningen-browser`. Для pinned official Playwright image start command
генерируется `node scripts/huurwoningen-browser-bootstrap.cjs`; он содержит только версионированный код.
Настройки worker аналогичны Funda: `BROWSER_PUBLIC_ORIGIN`, `BROWSER_ACCESS_KEY`, `BROWSER_ACCESS_EXPIRES_AT`,
`BROWSER_STATE_KEY_HEX`, `BROWSER_WORKER_TOKEN`, volume `/data`, healthcheck `/health`, память 2 ГБ.
Ключи, cookies и ссылки доступа не сохраняются в Git, Notion или логах.

CAPTCHA/HTTP 401/403 переводят источник в BLOCKED. Один recovery alert на эпизод приходит через outbox.
В браузере пользователь проходит проверку, нажимает «Поиск жилья», затем «Сохранить сессию».
Возобновление требует валидной выдачи; корректный нулевой результат тоже принимается.
Незавершённая проверка (включая `Even geduld...`) не позволяет сохранить recovery: API возвращает 409, кнопка сохранения выключена.
Обработчик запросов допускает ранние запросы к источнику и iframe Cloudflare до создания frame; ошибки закрытого route не завершают процесс.
Xvfb выделяет свободный дисплей через `-displayfd`, дочерний процесс завершается вместе с Node: перезапуск не зависит от оставшегося lock `:99`.
Обязательные проверки человека автоматически не решаются. Авторизация для чтения публичной выдачи при первоначальной проверке не понадобилась.

## Проверки

`node --test test/huurwoningen.test.mjs` проверяет fixture реальной карточки, сохранение фильтров,
пагинацию, неполную выдачу, CAPTCHA и ограничения. Полный CI также проверяет две независимые базы объявлений,
baseline, lease, дедупликацию уведомлений и recovery на disposable PostgreSQL.

Первоначальная live-проверка 12 октября 2026: HTTP 200, 198 объявлений, 7 страниц;
публичная карточка содержит цену, площадь, комнаты и JSON-LD. Итоговый smoke собирает все страницы через worker.

## Инцидент 13 октября 2026

В 16:26–16:27 CEST browser service завершился из-за необработанного `request.frame()`
на раннем navigation request. Затем перезапуски фиксировали `DISPLAY_EXITED` на статическом `:99`.
Перед падением Cloudflare показывал `Even geduld...`, который inspect ошибочно считал `humanCheck=false`.
Исправления покрыты регрессионными тестами маршрутизации, отказа дисплея, классификации CAPTCHA
и допуска recovery только после валидной выдачи. Это не подтверждает решение реальной CAPTCHA:
после развёртывания необходимы ручная проверка и read-only smoke согласованного поиска.
Если challenge продолжает зацикливаться, сохранить источник BLOCKED и отдельно проверить
совместимость удалённого браузера/сети с Huurwoningen; повторы галочки не являются подтверждением доступа.
