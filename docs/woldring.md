# Woldring Verhuur

[Согласованные требования в Notion](https://app.notion.com/p/402d10c6e6ab81d494ccf25dc2f3d470?pvs=204). Runbook описывает реализацию;
датированные результаты ниже относятся к конкретным проверкам, а не live-статусу production.

Квартиры: https://woldringverhuur.nl/appartementen/ ; студии: https://woldringverhuur.nl/studios/ .
HTTP source включается автоматически вместе с приложением, проверяется каждые
`MONITOR_INTERVAL_SECONDS` (900 секунд по умолчанию), отправляет новинки в существующий Telegram outbox.
Source ID: `woldring:apartments-studios`; отдельный baseline и PostgreSQL lease, без новой браузерной инфраструктуры.

Читаются обе полные категории; число карточек должно совпадать с `resultaten` для каждой.
Первая успешная проверка сохраняет доступные и недоступные объекты без массовых уведомлений.
Далее уведомляются новые доступные объекты и переходы `unavailable → available`.
Уникальный outbox key на объект/канал исключает повторное уведомление того же объекта.
Карточки `Niet beschikbaar` сохраняются только для сравнения статусов и никогда не рассылаются.
Ограничений цены, площади, свежести публикации или срока заселения нет; комнаты и парковки не читаются.

`Per direct beschikbaar!` означает доступность сейчас; `Beschikbaar per` — дату заселения, не публикации.
Цена, servicekosten, площадь, энергокласс, huurtoeslag и коммунальные услуги читаются из карточки.
Дата публикации отсутствует и не выдумывается. Сумма аренды и servicekosten не называется полной стоимостью проживания.
Пометка `Inschrijving gesloten` сохраняется и показывается в уведомлении; статус доступности сам по себе не обещает открытый приём заявок.
Дополнительные детали сохраняются в `HousingListing.rawSourceRef` как JSON снимок публичных параметров.

Один проход: 2 HTTP GET, максимум 8 МБ на страницу и 120 секунд суммарно.
Временные 502/503/504 и сетевые ошибки получают не более трёх попыток.
Redirect не выполняется; URL ограничены HTTPS доменом Woldring. 429 даёт cooldown,
401/403/проверка человека — BLOCKED и повторная read-only попытка не ранее шести часов.
Неполная выдача, неизвестная доступность и повреждённые параметры — ошибка, не нулевой результат;
неудача не меняет baseline или последний успешный запуск. Другие источники работают независимо.

Проверки: `node --test test/woldring.test.mjs`; PostgreSQL integration проверяет baseline,
переходы доступности, отдельный source, lease, отсутствие дублей и rollback при сбое.
Live smoke выполняет `collect()` на обоих реальных каталогах в отдельном CI workflow;
нормализованные карточки и подтверждённые counts не содержат секретов.
