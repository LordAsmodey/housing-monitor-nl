# GoHome — исследование подключения

Проверено 19.10.2026. Ниже исходное исследование до реализации.
Текущее подключение описано в [инструкции GoHome](../gohome.md). Актуальная архитектура прочитана через Notion:
[источник требований](https://app.notion.com/p/3f6d10c6e6ab81fe8b06e6eebb9c9455).
Проверены публичный HTML, JavaScript приложения, реальные ответы API, robots.txt
и опубликованные условия. Запросы выполнялись без аккаунта, Authorization и cookies.

## URL и фильтры

[Поиск пользователя](https://resident.gohome.io/zoeken/?f=eyJsb2NhdGlvbiI6Ikdyb25pbmdlbiIsIm1pblByaWNlIjo1MDAsIm1heFByaWNlIjoxNTAwfQ&city=Groningen).

`f` — JSON, закодированный UTF-8 Base64URL без padding. Это не ключ доступа,
не подпись и не идентификатор сессии:

```json
{"location":"Groningen","minPrice":500,"maxPrice":1500}
```

Frontend кодирует только location, minPrice, maxPrice, minRooms, maxRooms,
sortField, sortOrder. `city` используется как fallback, если нет валидного `f`.
При генерации ссылки надо синхронно обновлять оба параметра. Пагинация интерфейса:
`page=2` означает API pageIndex=1. По умолчанию открыта вкладка properties;
`tab=collections` — отдельные коллекции, их нельзя незаметно смешивать с квартирами.

Обычный GET страницы возвращает только оболочку React (1693 байта на проверке).
Парсинг HTML выдачи не подходит. Источник контракта:
[публичный bundle](https://resident.gohome.io/static/js/main.dd2034f8.js),
имя которого может измениться после обновления сайта.

## Подтверждённый публичный API

API origin: `https://qb4ubme4cj.execute-api.eu-central-1.amazonaws.com`.
Frontend соединяет base `/prod/` и endpoint `/v1/...`, поэтому фактически
использует двойной слеш после prod; именно этот вариант проверен:

```http
POST /prod//v1/public/property/listProperties
Content-Type: application/json

{"teamId":1,"pageIndex":0,"pageSize":15,"location":"Groningen","minPrice":500,"maxPrice":1500}
```

Это поиск для чтения, несмотря на HTTP POST. Ответ:
`{totalPropertiesCount: number, properties: [...]}`.
На проверке total=26: pageIndex=0 дал 15 записей, pageIndex=1 — 11,
26 уникальных propertyId, все location=Groningen, цена €630.82–1300.
Три записи isRented=false, 23 — true. Отсутствие фильтра доступности в URL
означает, что сданные объекты тоже присутствуют в поиске.

Поля списка: propertyId, title, urlSlug, location, minimumRent, livingArea
(строка либо null), nrOfRooms, imageUrl, createdTimestamp, updatedTimestamp,
isRented, availableFromDate, type, propertyCollectionDetails.
`type.name=Property` не означает квартиру: тип жилья находится в деталях.

Детали читаются без авторизации:

```http
GET /prod//v1/public/property/getPropertyBySlug/planetenlaan-495-a-groningen
```

Проверены детали ID 9128 и 2578. В них есть id, urlSlug, isRented,
offerType, listedDate, propertyDetails (city, country, type, published,
minimumRent, address, availableFromDate, description), propertyFeatures и media.
Подтверждены offerType=RENTAL, propertyDetails.type=APARTMENT и published=true.
Ссылка пользователю: `https://resident.gohome.io/te-huur/{urlSlug}`.

Контрольный поиск Groningen с ценой €1–2 вернул
`{"totalPropertiesCount":0,"properties":[]}`. Это подтверждает форму пустого ответа,
но не гарантирует корректность любого будущего нуля при штатных фильтрах.

## Особенности данных

- Три не сданных объявления на момент проверки: Planetenlaan 495 A (€1083),
  Oosterhamrikkade 13 c (€884.79), Planetenlaan 431 (€1221.21).
  Это статус сайта; детали третьего объекта не проверялись.
- Planetenlaan 495 A — только для студентов вне муниципалитета Groningen,
  временная аренда максимум 18 месяцев. В описании €175 отопление и €40 servicekosten.
  Общая сумма отличается от minimumRent; эти расходы не включены в фильтр €500–1500.
- Oosterhamrikkade 13 c — APARTMENT; livingArea в списке null, описание сообщает
  45 м² и servicekosten €40. Структурированная дата заселения 01.12.2026,
  но в одном пункте описания осталась 01.11. Безусловная согласованность данных
  сайта отсутствует. Не заменять неизвестную площадь нулём и не выдавать
  availableFromDate за дату публикации.
- isRented=false само по себе не доказывает пригодность для пользователя.
  Нужны детали, фильтр самостоятельности жилья и отдельное решение об исключении
  студенческой/временной аренды. Пользовательская ссылка такие исключения не задаёт.

## Рекомендуемая реализация в текущем проекте

1. HTTP JSON collector без Chromium, browser state и LLM. Фильтры хранить
   структурированно, отправлять в JSON body; Base64URL генерировать только для ссылки
   админки. Сохранить Groningen и €500–1500 из пользовательской ссылки.
2. Отдельные gohome-core.ts, gohome-runner.ts, gohome.service.ts по существующему
   шаблону HTTP-источников, source ID например `gohome:groningen-homes`.
   Добавить search-settings, environment flag, админку и smoke script при реализации.
3. Читать все страницы по 15. Проверять схему ответа, неизменность total,
   ожидаемые размеры страниц, итоговый счётчик, уникальность ID/URL до фильтрации.
   Повторно проверять город и цену локально. Задать лимиты страниц, тела и времени.
   Динамические перемещения между страницами не всегда выявляются счётчиками;
   API не предоставляет доказанной snapshot-консистентности.
4. Читать детали подходящих кандидатов; сверять ID, slug, адрес/город и цену.
   Для уведомления требовать явные isRented=false, published=true, offerType=RENTAL
   и согласованный самостоятельный тип жилья. Unknown исключать из доступных;
   сбой деталей не превращать в успешный частичный результат.
5. Дедупликация по propertyId, canonical URL без поисковых параметров.
   Отдельный тихий baseline, transactional outbox, PostgreSQL lease, расписание
   900 секунд; новые доступные объекты и повторная доступность по текущему контракту.
   Ошибка API/401/403/429/HTML вместо JSON не означает ноль объявлений.
6. Allowlist для resident.gohome.io и точного API origin с ограничением путей;
   проверять редиректы. CloudFront images не загружать в collector без необходимости.
   Перед выпуском — fixtures, пагинация/дубли/смена total/пустой ответ, доступность,
   интеграционные тесты baseline/outbox/pause, полный live smoke без рассылки.

## Опубликованные правила и границы проверки

[robots.txt](https://resident.gohome.io/robots.txt) содержит `User-agent: *`
и пустой `Disallow`. Это не разрешение на любое использование данных.
[Условия GoHome](https://gohome.io/algemene-voorwaarden/), раздел 7.1,
содержат ограничения коммерческого screen scraping, создающих помехи средств,
а также копирования/распространения информации без предварительного письменного
разрешения с оговоркой о допустимом законом. Эти положения следует учесть перед
регулярным сбором и пересылкой в Telegram; наличие разрешения пользователем
на момент исследования не сообщалось. Это фиксация текста сайта, не правовая оценка.

Публичный API технически работает, но документированная внешняя API-гарантия,
rate limits, RSS/webhook и длительная стабильность не установлены.
Production egress, полный проход с деталями всех объектов и Telegram не проверялись.
