# Sentry

Приложение отправляет ошибки запуска, необработанные исключения и отклонения Promise,
ошибки проверок Funda/Huurwoningen/Woldring, сбои outbox tick, DEAD_LETTER и UNCERTAIN.
Отдельные браузерные сервисы пока не инструментированы: ошибки их запросов видны
через приложение, падение браузерного процесса проверяется в Railway.

## Настройка

На сервисе Railway `housing-monitor-nl` задайте `SENTRY_DSN` из Client Keys проекта
и `SENTRY_ENVIRONMENT=production`. Локально можно сохранить DSN в игнорируемом `.env`.
DSN не является auth token; доступ к чтению событий он не даёт. Auth token не нужен
для отправки событий и не должен находиться в production-приложении.
`SENTRY_RELEASE` необязателен: по умолчанию используется `RAILWAY_GIT_COMMIT_SHA`.
Без DSN интеграция выключена. Сбой SDK/его транспорта не останавливает мониторинг;
при ошибке инициализации выводится только контролируемое `SENTRY_INIT_FAILED`.

После развёртывания выполните явно:

```sh
npm run sentry:smoke
```

Команда создаёт одно событие категории `SENTRY_SMOKE_TEST`, печатает event ID и ждёт
flush до двух секунд. `accepted=true` подтверждает HTTP 2xx от Sentry ingestion, но не
доказывает появление события в интерфейсе: найдите event ID в Sentry и проверьте
environment/release. Ошибки сети могут диагностироваться дополнительно по Sentry.
Тестовое событие не отправляет Telegram-сообщения и не читает объявления.

## Изоляция автоматических тестов

При `NODE_ENV=test` или наличии `NODE_TEST_CONTEXT` интеграция полностью выключена:
SDK не загружается и не инициализируется, ошибки и cron check-ins не отправляются.
Node устанавливает `NODE_TEST_CONTEXT` в процессе `node --test`, поэтому защита
работает для `npm test` и `npm run test:integration`, даже если DSN унаследован
из окружения или Prisma подгрузила локальный `.env` при создании клиента.
Это не зависит от `SENTRY_ENVIRONMENT`: значение `development` само по себе
не выключает отправку при обычном запуске приложения.

Тест SDK использует явно внедрённые параметры и транспорт в памяти; сетевых
запросов он не делает. Живая диагностика остаётся отдельной явной командой
`npm run sentry:smoke` вне test-процесса. В `NODE_ENV=test` smoke завершается
ошибкой, поскольку отправка запрещена.

12.10.2026 до этой защиты тест outbox создал development-событие
`DELIVERY_DEAD_LETTER` ([HOUSING-MONITOR-NL-3](https://objectvalue.sentry.io/issues/153151349/)).
Его culprit — `outbox.test.ts`: тест специально исчерпывает повторные попытки
доставки. Это не production-сбой. Старые тестовые карточки можно отметить как
Resolved вручную; исправление предотвращает новые отправки, но не удаляет историю.

## Чтение ошибок через API

Для локального плагина Sentry создайте personal auth token в
[Personal Auth Tokens](https://sentry.io/settings/account/api/auth-tokens/) с
правами `event:read`, `project:read`, `org:read`. Сохраните его только в игнорируемом
локальном `.env` как `SENTRY_AUTH_TOKEN`, рядом можно задать `SENTRY_ORG=objectvalue`
и `SENTRY_PROJECT=housing-monitor-nl`. Токен не публикуется в Git и не нужен Railway.
Python-скрипт плагина читает переменные процесса: `.env` нужно загрузить в окружение
его запуска, сам скрипт файл не читает. Токен и сырые персональные данные не выводятся
при диагностике.

## Какие данные уходят

Только категория ошибки, теги source/component/category, время, environment/release,
тип `MonitorError` и позиции стека с именами файлов. Исходное сообщение исключения,
полные пути, source lines, локальные переменные, request, user, extra, contexts и
breadcrumbs удаляются фильтром beforeSend. Автоматические логи и client reports
отключены; трассировка производительности не включена. Environment/release должны
быть техническими идентификаторами без секретов. Группировка разделяет компонент,
источник и категорию.

## Проверки расписания

`SENTRY_CRONS_ENABLED=true` включает мониторы `housing-funda`,
`housing-huurwoningen`, `housing-woldring` после получения PostgreSQL lease.
Успех/ошибка завершает тот же check-in. Пропущенные из-за lease или расписания
проверки не создают событий. Интервал берётся из MONITOR_INTERVAL_SECONDS,
допуск — 5 минут, max runtime — 7 минут, ошибка после двух неудач подряд.

По умолчанию Crons выключены. BLOCKED/CAPTCHA и cooldown законно приостанавливают
проверки: включённый монитор расписания может показать пропущенный check-in даже
при штатной блокировке. Включайте Crons только с учётом этой политики и доступной
квоты Sentry. Настройка правил оповещения выполняется отдельно в Sentry.
